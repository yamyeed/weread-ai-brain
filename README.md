# WeRead AI Brain — 微信读书 AI 阅读外脑

> 不只是看数据，而是让 AI 替你想、替你连、替你重构知识

你的微信读书里，是不是躺着几百条划线和想法，但从来没复盘过？

读完的书像水过鸭背，划过的线再也没看过第二眼？

书架上几十本书，却说不清自己到底在哪个领域扎了根、哪个领域是盲区？

**WeRead AI Brain** 就是来解决这些问题的。它不是又一个阅读统计工具，它是你的**阅读外脑**——替你看数据、替你想问题、替你把散落的笔记连成知识网络。

---

## 🧠 它能做什么？

三大核心能力，覆盖从「看见数据」到「深度思考」到「带走知识」的完整闭环：

### 📊 看得见 — 数据可视化看板

把沉睡在微信读书里的数据变成一眼就能读懂的看板：

**12 周阅读打卡绿墙**
GitHub 风格的热力图，过去 12 周每天读了多少一目了然。5 级颜色从 ⬜（0 分钟）到 🟦（60 分钟+），连续打卡的成就感比任何打卡 App 都上头。

**24h 阅读脑波频段**
统计你所有划线和想法的时间戳，画出 24 小时活跃度柱状图。你是清晨专注型还是深夜灵感型？数据会告诉你答案。峰值时段自动标注 🧠 标记。

**知识品类光谱 + AI 认知盲区诊断**
统计书架书籍分类，用进度条展示你的知识结构分布。然后 AI 会诊断你的认知盲区——比如「互联网产品占 65%，人文与社会只有 15%，你的思维框架偏工具理性，缺少对复杂人性和社会结构的理解」。诊断完还会推荐跨界破局书单，告诉你该补什么。

**WeRead-MBTI 阅读灵魂卡片**
4 个维度、16 种阅读人格，你是哪种？

| 维度 | 含义 | 判定逻辑 |
|:--|:--|:--|
| B/D | 广博 vs 深挖 | 分类多且完读率低 → B；专注深耕 → D |
| L/H | 理性 vs 人文 | 工具/经管占比高 → L；文学/历史/哲学高 → H |
| A/R | 实践 vs 吸收 | 划线密度高 → A；静读少划线 → R |
| T/S | 规律 vs 随兴 | 固定时段连续打卡 → T；时间飘忽突发 → S |

16 型人格各有灵魂判词，比如：
- **BLAS**「终身创业体验卡持有者」— "刚看了一页商业模式，等一下，我先用 Cursor 搓个 MVP 出来。"
- **DLAT**「方法论无情推土机」— "早上 7 点，必须把这本硬核工具书拆解成 24 个思维模型。"
- **DHRS**「失眠夜的灵魂漫游者」— "不需要任何人知道我在读什么，4 点的失眠夜，书是我的避难所。"

**AI 深度分析卡片（v2.0.0 新增）**
看板中可嵌入 AI 对指定书籍的深度分析结果，琥珀→粉→蓝渐变发光边框，视觉上和 MBTI 卡片的紫色发光形成区分。

**双模式输出**
- **Markdown 看板**（默认）：对话中直接输出，方便追问和交互
- **HTML 卡片看板**（可选）：经用户确认保存路径后生成精美单文件 HTML；保存后只报告路径，不执行系统打开命令

### 🧠 想得深 — AI 深度分析

同一本书，换个视角就是不同的世界。三种专业分析模板：

**📖 概念通解**
遇到抽象概念、陌生理论、技术术语，AI 用日常类比帮你建立直觉理解。比如「贝叶斯推断」→ "就像你根据今天的天气修正明天带伞的概率，每多一条证据就更新一次判断。"

**📋 PM 拆解**
产品经理视角，从商业书和案例中提取业务逻辑、用户痛点、产品功能点，并给出 2 个改进建议或竞品思路。读《启示录》不只是看故事，而是拆出可落地的方法论。

**⚖️ 法务排雷**
合规律师视角，识别合同条款、商业案例中的合规风险、数据隐私隐患、违约漏洞，用大白话指出需要避开的坑。读商业案例不再只看成功故事，也能看到法律地雷。

**上下文联动**
分析不局限于你选中的那一段。经你明确同意后，AI 可读取该书的**历史划线和想法**作为上下文，结合你在整本书中的思考轨迹进行分析。你在第 3 章划的线和第 7 章写的想法，会被串联起来。

**跨书关联**
指定一个主题，AI 从书架中找到 2-5 本相关书籍，先列出拟读取的书籍和数据范围；经你确认后再读取笔记，找出跨书的概念映射、矛盾观点、递进关系。比如《思考，快与慢》和《噪声》对「判断偏差」的观点如何碰撞？《原则》和《反脆弱》对「系统设计」的思路如何递进？

---

### 📝 带得走 — 知识重构与导出

**语义笔记聚类**
跨书按核心概念聚合划线。比如「认知偏差」这个概念，可能同时出现在《思考，快与慢》《噪声》《清醒思考的艺术》里，AI 把相关划线和想法聚在一起，加上跨书综合洞察，经你确认内容和保存路径后输出 Obsidian 友好的 Markdown。

**单书分析导出**
分析完成后可导出为结构化 Markdown，包含原文摘录、AI 分析结果、上下文关联。导出前会说明文件内容和保存路径，并等待你的确认。

## 🔧 技术实现

**数据来源**：微信读书官方 API Gateway（`https://i.weread.qq.com/api/agent/gateway`），POST 统一网关，Bearer Token 鉴权。所有数据通过官方接口获取，不抓包、不逆向、不存储。

**API Key 获取**：微信读书 App → 我 → 设置 → 微信读书 Skill → 扫码，获取 `wrk-` 开头的 API Key。

**支持的 API**：

| 用途 | 接口 |
|:--|:--|
| 书架列表 | `/shelf/sync` |
| 阅读统计 | `/readdata/summary`、`/readdata/detail` |
| 搜索书籍 | `/store/search` |
| 书籍详情 | `/book/info` |
| 划线笔记 | `/book/bookmarklist` |
| 个人想法 | `/review/list/mine` |
| 阅读进度 | `/book/getprogress` |

**隐私**：数据仅发送到微信读书官方统一网关并在本地处理，不上传任何第三方服务器。API Key 仅从本地环境变量读取。除非你明确要求导出，否则不会把划线、想法或分析结果写入本地文件。

**安全边界**：

- 只有请求中明确提到「微信读书」或「WeRead」时才会启用本 Skill，普通的「分析」「看板」「MBTI」等请求不会误触发。
- 单书任务只读取完成该任务所需的单书数据；跨书读取前会列出书名和数据范围并等待确认。
- Skill 元数据显式声明运行所需的 `WEREAD_API_KEY`、`curl` 和 `python3`。
- 辅助脚本只允许访问固定的 HTTPS 官方网关；TLS 或 HTTP 失败时立即停止，不会降级协议或宽松重试。
- 保存 HTML、Markdown 等本地文件前，会说明内容与路径并等待确认；默认建议保存到当前工作区的 `outputs/` 或 `weread-exports/`。
- 生成的文件不会通过系统命令自动打开；HTML 模板仅使用系统字体，不加载 Google Fonts 等第三方资源。

辅助脚本也有独立隐私闸门：联网命令必须显式传入 `--confirm-private-data`，且会在请求前显示微信读书官方网关地址和本次数据范围。只有用户已经确认该次读取后才能传入此参数。

## 🚀 快速开始

1. 获取 API Key：微信读书 App → 我 → 设置 → 微信读书 Skill → 扫码
2. 配置：`export WEREAD_API_KEY=wrk-你的密钥`
3. 开始使用：
   - 「微信读书生成看板」— 查看完整数据看板
   - 「微信读书分析《启示录》」— AI 深度分析指定书籍
   - 「WeRead PM 拆解《启示录》」— 产品经理视角拆解指定书籍
   - 「微信读书跨书关联」— 多本书交叉分析，读取前确认
   - 「微信读书导出笔记」— 语义聚类导出，写入前确认
